## P3.1, P3.6, P3.7 — Portal-shells till React Server Components

**Status:** Klient-renderad. `(portal)/layout.tsx` och flera underliggande sidor är `"use client"` så hela portal-shell:en hydratar i webbläsaren för att läsa session, vilket ger flash + onödig JS-payload.

**Vad som krävs:**
1. Skapa en RSC-variant av `(portal)/layout.tsx` som läser session server-side via `cookies()`/`headers()`.
2. Splittra nuvarande layout i `PortalShellServer` (RSC) + `PortalShellClient` (för interaktivitet som sidebar-state, theme-toggle).
3. Migrera de mest besökta portal-sidorna (`/portal`, `/portal/saljare`, `/portal/statistik`) till RSC + streaming-data via `Suspense`.
4. Bibehåll de mutations-tunga sidorna (`/portal/offerter`, `/portal/installningar`) som klient-renderade tills tRPC kan kalla från Server Actions.

**Estimat:** 3–5 dagar. Berör auth-helpers (kräver server-friendly variant av `useSession`), tRPC-context, samt revalidation-stratergi.

**Nuvarande mitigation:** I `useApiData`-hook har vi nu standardiserad fetch-hygien med AbortController + retry, och `if (!user) return null` förhindrar flicker (3.3) tills RSC-migreringen är klar.

## P3.5, P3.8, P3.9, P3.10 — Zod-schemas på alla API-handlers

**Status:** Vi använder Zod i tRPC-routern och ett fåtal REST-endpoints, men majoriteten av Hono-routes parsar `await c.req.json()` direkt och castar till en hand-skriven interface.

**Vad som krävs:**
1. Skapa `packages/contracts/src/schemas/` med en `*.schema.ts` per resurs (order, campaign, team-invite, etc.).
2. Lägg en Hono-middleware `validateBody(schema)` / `validateQuery(schema)` som returnerar 400 med konsekvent error-shape.
3. Migrera route-fil i taget, börja med checkout + auth + contact (höst attack-yta).
4. Generera TS-typer från schemas och ersätt nuvarande hand-skrivna interfaces.

**Estimat:** 1–2 sprintar (mekanisk men >40 endpoints). Lägg upp som tracking-issue.

## P3.14, P3.17, P3.18 — `requireSession` middleware-refactor

**Status:** Varje route gör `const session = c.get("session")` + `if (!session) return c.json({error: "unauthorized"}, 401)`. Det leder till duplicerad kod och missade auth-checks.

**Vad som krävs:**
1. Skapa `requireSession()`-middleware som plockar session och kastar 401 om saknas, samt sätter `c.set("user", session.user)`.
2. `requireRole("ASSOCIATION_ADMIN")` ovanpå för RBAC.
3. Migrera routes i grupper (start med /admin/*, /portal/*, /v1/account/*).
4. Lägg ESLint-rule som varnar om `c.get("session")` används utanför middleware-helpers.

**Estimat:** 2–3 dagar. Risken är att en bugfix-window krymper därför börja på staging.

## P3.27 — Audit-log immutability + retention

**Status:** `audit_logs`-tabellen är vanlig Postgres-tabell — admin kan i teorin truncate:a. Vi har inget retention-policy och inga signed log-rader.

**Vad som krävs:**
1. Postgres `REVOKE DELETE, UPDATE, TRUNCATE` på `audit_logs` för app-rollen (skapas via migration).
2. Cron-job som efter N dagar dumpar äldre rader till en append-only WORM-bucket (S3 Object Lock i compliance-mode).
3. Optional: HMAC-kedja per row (`prev_hash → row_hash`) så manipulation blir detekterbar.
4. UI-notice i admin: "Logs äldre än X månader hittas i cold storage".

**Estimat:** 1 vecka. Berör ops (IAM på bucket), DB-rättigheter, ett nytt cron-job.

## P3.33, P3.34 — Settlement skatte-precision (P3.44/3.45 sammanslaget)

**Status:** Vi räknar moms genom `Math.round(amount * 0.2 * 100) / 100` på utdragna rader. För enskilda ordrar blir det rätt, men ackumulerade payouts kan drifta 1–2 öre p.g.a. floating-point.

**Vad som krävs:**
1. Migrera all monetär matte till `bigint`-baserad "minor units" (öre).
2. Använd Postgres `numeric(12,2)` för utdrag och konvertera i applikationen.
3. Skriv property-tester (fast-check) som genererar 10k ordrar och verifierar att `sum(rows.vat) == settlement.vat_total`.

**Estimat:** 2 dagar för migration + tester. Kräver schema-ändring och en stale-data-backfill.

## P3.37 — Public chat-widget RAG

**Status:** Chatten skickar bara meddelandet till OpenAI utan kontext. Brand-tone-prompten finns men inga kunskapsdokument (FAQ, produktbeskrivningar) injiceras.

**Vad som krävs:**
1. Bygg en embedding-pipeline över produktbeskrivningar, FAQ, blogginlägg.
2. Använd pgvector i samma Postgres-instans (`packages/db/migrations/xxxx_embeddings.sql`).
3. Per request: embed:a user-message → toppmatchningar → injicera som `system`-kontext.
4. Lägg en `documents`-tabell + admin-UI för att hantera RAG-källor.

**Estimat:** 1–2 veckor. Tror inte vi behöver det förrän chat-trafik är >100/dag.

## P3.62 — Open Claw MCP-rollout

**Status:** Vi har MCP-grunden i `apps/api/src/lib/ai/mcp/` men ingen produktyta använder den.

**Vad som krävs:**
1. Välj första tool-pack: föreslår "föreningsadmin"-pack (`list_campaigns`, `create_team_invite`, `get_payout_status`).
2. Implementera tool-handler-skiktet med RBAC (tools får bara köra på data användaren själv har access till).
3. Lägg en feature-flagga `OPEN_CLAW_MCP_ENABLED` och rulla ut till en pilot-förening.
4. Logga `mcp.tool.invoked` i audit-loggen.

**Estimat:** 1 sprint för första tool-pack + lite UI för att aktivera. Större strategiskt beslut: vill vi committa till MCP-API:t eller bygga eget? Behöver produkt-buy-in.

## P3.63 — AI moderation / output-filter

**Status:** Vi har system-prompt som ber modellen vara nice men ingen prog-validering av output. En jailbreak kunde få modellen att läcka system-prompt eller skriva off-brand.

**Vad som krävs:**
1. Lägg `moderation`-anrop (OpenAI Moderation eller egen klassifierare) pre + post.
2. Output-validator som drar tillbaka svar med svordomar/PII/konkurrent-namn.
3. Eskalations-flöde: vid filter-trigger → spara fullt request/response i admin-audit för granskning.
4. Användar-feedback "den här svaret kändes inte rätt" → automatisk eskalation.

**Estimat:** 3–4 dagar. Måste passera en juridisk review (vi loggar då sub-set av användarprompt — privacy).

## P3.65 — Focus-trap för portal sidebar drawer

**Status:** Mobile-sidebar är fungerande Sheet men focus loop:ar inte korrekt — Tab kan hoppa ut till bakgrundens kontroller.

**Vad som krävs:**
1. Wrap Sheet-innehåll i `FocusScope` (Radix har en eller använd `focus-trap-react`).
2. Lägg first-element auto-focus när sheet öppnas.
3. Restore focus till trigger-knapp vid stängning.
4. Skriv Playwright a11y-test som verifierar Tab-cykel inom drawer.

**Estimat:** 1 dag + tid att skriva test. Vänta tills portal-sidebar-refactor (P3.1/3.6/3.7) är klar, annars dubbel-arbete.

## P3.80 — Radius-skala drift

**Status:** Tailwind-defaults blandas med `rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-[14px]`, `rounded-full` utan dokumenterad regel. Buttons använder ibland `rounded-md`, ibland `rounded-xl`.

**Vad som krävs:**
1. Inventera nuvarande radius-användning (skript som listar alla `rounded-*` per komponent).
2. Definiera en skala: `radius-card`, `radius-input`, `radius-pill`, `radius-full`.
3. Lägg som CSS-variabler i `globals.css` och migrera komponenter.
4. ESLint-rule som varnar för arbitrary `rounded-[NNpx]`.

**Estimat:** 2 dagar för inventering + migration. Hör hemma i en större design-system-pass tillsammans med shadow- och spacing-token-skalor.
