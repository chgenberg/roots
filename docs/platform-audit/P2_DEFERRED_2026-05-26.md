## P2.2 — Refund API

**Status:** Inte påbörjat. `customer_order_status` har redan `REFUNDED` men ingen endpoint sätter den.

**Vad som krävs:**
1. `POST /v1/checkout/refund/:orderId` (RBAC: `INTERNAL_ADMIN` initialt, senare `ASSOCIATION_ADMIN` för egen org).
2. Kalla Klarna `order-management/v1/orders/{id}/refunds` med belopp + ref.
3. Skapa motsvarande kredit-faktura via `getInvoiceProvider().createCreditInvoice()` (måste läggas i providern).
4. Markera `customerOrders.status = "REFUNDED"` + `refundedAt` (ny kolumn behövs).
5. Justera settlement-generationen så återbetalda orders inte räknas in i payouts.
6. Audit-event `order.refunded` med belopp och initiator.

**Estimat:** 2–3 dagar inkl. tester. Berör schema, payments-lib, settlement-logik och frontend (refund-knapp + status-UI).

## P2.3 — Fortnox webhook activation

**Status:** Endpoint existerar (`/v1/integrations/fortnox/webhook`) men är en no-op stub. `payouts.invoiceStatus` updateras därför aldrig automatiskt när Fortnox markerar fakturan betald.

**Vad som krävs:**
1. Definiera vilka Fortnox-event vi prenumererar på (`invoice.paid`, `invoice.cancelled`, `invoice.credited`).
2. Implementera HMAC-verifiering av Fortnox-signatur (`runbooks/onboard-fortnox.md` har formatet).
3. Mappa event → payout-status. `invoice.paid` → `payouts.status = "PAID"` via samma kod som `PATCH /payouts/:id/status` (extract:a en internal helper).
4. Idempotens via `webhook-dedup.ts` på Fortnox event-id.
5. Audit-event `payout.paid` med `source: "fortnox_webhook"`.

**Estimat:** 1–2 dagar. Block:eras av att vår Fortnox-app måste få webhook-prenumerationen aktiverad — kräver vendor-touch.

## P2.30 — OpenClaw gateway

**Status:** AI går idag direkt mot OpenAI via `apps/api/src/lib/ai/openclaw-client.ts` (namnet är historiskt). Den planerade OpenClaw-gateway:n (egen prompt-cache, fan-out till flera LLM-leverantörer, kostnads-attribution per org) är inte implementerad.

**Vad som krävs:**
1. Beslut om vi bygger själva eller använder LiteLLM / Helicone / Portkey som proxy.
2. API-kontrakt mellan vår `chatCompletion()` och gateway:n (likt OpenAI-format).
3. Routing-policy: vilka prompts går till `gpt-5.4`, vilka till `claude-4.6-sonnet` osv.
4. Per-org rate-limit, kostnads-budget och audit av `model`, `tokens_in`, `tokens_out`.
5. Migrate hair-analysis och chat-rutterna till nya gateway:n.

**Estimat:** En sprint. Behöver eget tech-design-dok innan kod.
