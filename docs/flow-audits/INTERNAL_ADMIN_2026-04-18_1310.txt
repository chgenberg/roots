OPS GUARDRAILS — TOP RISKS
-----------------------------
1. **`audit_logs` table is never written or queried in app code** — admin/support actions, role changes, and future impersonation would leave **no structured trail**.
2. **Portal REST RBAC inconsistencies:** `GET /v1/portal/pipeline` aggregates **all quotes** with only `requireSession`; **`GET /sellers`** returns sales roster (PII) without **`INTERNAL_ADMIN`** guard — **cross-tenant / least-privilege violations**.
3. **`GET /statistics` and `GET /income`** use `where(session.orgId ? … : 1=1)` — users with **null `orgId`** receive **platform-wide** aggregates/revenue — unintended global BI exposure.
4. **Ops decisions driven by misleading UI:** Admin dashboard mixes **demo fallbacks** with partial live data; **`mrrOre`** is cumulative paid order sum, **not MRR**; KPI keys (`mrr`, `activeClubs`) **don’t match API** (`mrrOre`, `totalClubs`) → **false zeros and trust collapse**.
5. **No campaign oversight or support playbooks** in product — pause/extend/flag require **association-only** tRPC; internal admin **cannot intervene** via the same mutations; **no global campaign list/export**.

GDPR / AUDIT GAPS
-----------------
- **No GDPR erasure/delete-user API** path found in `apps/api` (grep); **no SAR / registerutdig workflow** in portal — only marketing `integritet` text.
- **No full subject data export** bundle (profile, orders, consents, chats) — `generateOrdersCsv` exists but is **not** a SAR pack and **unwired** to admin UI.
- **`audit_logs` DDL** has no append-only enforcement (no triggers/RLS cited) — table exists but **unused**.
- **Support “act on behalf”** (impersonation, password reset for user) **not implemented** by design (`05_AUTH_RBAC.txt`); `requestPasswordReset` tRPC is **stub** — no operational replacement with audit.
