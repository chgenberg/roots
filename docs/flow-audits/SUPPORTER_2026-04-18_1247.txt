CART ABANDONMENT TOP RISKS
---------------------------
1. **Checkout shows no line items, unit prices, subtotal, moms, or shipping fee** — only implicit `items` in POST; supporter cannot verify the basket on `/shop/[slug]/kassa` before continuing to payment.
2. **Cart lives in React state only** — reload clears cart; persistence is fragile URL-query serialization to kassa (`item_*`), long/unstable links.
3. **Inactive/ended campaigns remain browsable** — failure only at checkout create (“Kampanjen är inte aktiv”) with no earlier banner or recovery path.
4. **Shop vs kassa delivery mismatch** — shop reflects `campaign.deliveryType`; kassa always offers both Samleverans and Hemleverans — trust/confusion at decision time.
5. **iOS checkout inputs** — shared `Input` uses `text-sm` (~14px); likely viewport zoom on focus + submit CTA may sit below fold on small screens.

SELLER ATTRIBUTION ISSUES
--------------------------
- **`kassa` strips context:** Header is generic “Kassa” + back link — **no seller name, team, org, or campaign story** present on shop page (`page.tsx` ~152–185).
- **Sticky cart bar** shows count + total only — **does not repeat** “Köp av …” / team / cause.
- **`bekraftelse` share** uses title **“Köp via Roots”** and shop URL — weak **social proof** that the supporter just helped *this* seller (vs branded share-back story).
- **OG/metadata:** Personal shop is client-heavy — **no per-seller Open Graph** for pasted links (generic site preview); reduces recognizable seller context in messaging apps (conversion/trust adjacent to attribution).
