================================================================
SCOUT 1 — Public landing page
================================================================
Date: 2026-05-25 22:17
Scope: Marketing homepage shell — page.tsx, layout.tsx, root layout, hero*, header (nav), footer

SUMMARY
-------
The public landing page renders without broken routes and now includes proper legal identity in the footer and enriched Organization JSON-LD — improvements since the April 2026 flow audits. However, the above-the-fold story still reads as a D2C hair-care / håranalys funnel, not a föreningsfundraising platform; the hero loads ~5 MB unoptimized images as dual LCP candidates; and the primary CTA opens a lead dialog that silently opts users into newsletter consent. These three issues block MVP-ready quality for the stated B2B2C product.
Findings: 22 total (P1: 2, P2: 9, P3: 7, P4: 4)
MVP readiness: 58/100

P1 — CRITICAL (blocks MVP)
================================================================

[1.1] Hero primary CTA silently opts users into newsletter marketing
  File: apps/web/src/components/sections/hero-lead.tsx:10-21 → apps/web/src/components/hair-analysis-lead-dialog.tsx:164,193,210,305
  Symptom: Visitor clicks “Starta din håranalys” (the only pulsing primary CTA above the fold). After GDPR consent checkbox, the API payload always includes `newsletterConsent: true` with no visible marketing opt-in control.
  Root cause: `const [newsletterConsent] = useState(true)` is hard-coded; comment says consent is “included in privacy policy” but e-postmarknadsföring requires explicit opt-in under GDPR/ePrivacy.
  Fix: Add a separate unchecked checkbox (“Ja, skicka mig tips och erbjudanden via e-post”) bound to `newsletterConsent`; default `false`; only send `true` when checked. Wire through draft save/load.
  Effort: S
  Ref audit: PUBLIC [1.2] — STILL UNRESOLVED

[1.2] Hero LCP images are ~5 MB each, mislabeled PNG-as-JPG, both marked `priority`
  File: apps/web/src/components/sections/hero.tsx:10-30
  Symptom: On mobile (360px), first paint waits on `h1mobile.jpg` (~5.2 MB, actually PNG data). Desktop branch also loads ~4.8 MB with `priority`. Slow 3G/4G first visit shows blank hero for multiple seconds; Lighthouse LCP likely fails.
  Root cause: Source assets in `public/images/h1desktop.jpg` / `h1mobile.jpg` are uncompressed PNGs (2528×1696) saved with `.jpg` extension. Both `<Image>` branches use `priority`, so mobile may download two large candidates depending on hydration/CSS breakpoint.
  Fix: Re-export as WebP/AVIF at ≤200 KB mobile / ≤400 KB desktop; use `<picture>` or single responsive srcset; keep `priority` on one visible branch only; add explicit `width`/`height` or `placeholder="blur"`.
  Effort: M
  Ref audit: PUBLIC [3.1] — STILL UNRESOLVED (worsened by file size discovery)
