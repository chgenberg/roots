-------

Findings: 22 (P1: 7, P2: 8, P3: 5, P4: 2)
MVP readiness: 42/100

[1.2] Cannot end campaign in UI — settlement pipeline unreachable
  File: apps/api/src/routes/settlement.ts:67-69
        apps/api/src/routes/association.ts:405-504 (create → ACTIVE immediately)
        apps/web/src/app/(fundraising)/forening/ (no end-campaign control)
  Symptom: `POST /generate` returns 400 until `campaign.status === "ENDED"`. No REST or web path sets ENDED; tRPC `campaigns.update` exists but is unwired.
  Root cause: Lifecycle mutation only in unused tRPC router.
  Fix: REST `PATCH /v1/association/campaigns/:id/status` with ENDED transition + UI "Avsluta kampanj"; block new checkout when ENDED.
  Effort: M
  Ref: Scout 15 [1.4]; feedback 03_settlement [GAP statusmachine]

[1.3] Fortnox create-invoice uses empty orgNumber and wrong customer stub
  File: apps/api/src/routes/settlement.ts:249-267
        apps/api/src/lib/invoicing/fortnox-provider.ts:71-86
        packages/db/src/schema/organizations.ts (fortnoxCustomerId column unused)
  Symptom: `create-invoice` passes `name: "Roots AB"`, `orgNumber: ""`, `email: ""`. Fortnox `CustomerNumber` is set from empty orgNumber → API error in prod.
  Root cause: Settlement never loads organization row; hardcoded placeholder customer.
  Fix: Join `organizations` on `payout.orgId`; use `fortnoxCustomerId` or org number + billing email; reject if Fortnox customer missing with actionable error.
  Effort: M
  Ref: platform-audit [1.10], [2.15]; INTERNAL_ADMIN financial gap

[1.4] NullInvoiceProvider makes create-invoice always fail in dev/staging
  File: apps/api/src/lib/invoicing/null-provider.ts:21-30
        apps/api/src/routes/settlement.ts:269-274
  Symptom: When `FORTNOX_ENABLED !== "true"`, provider returns `externalId: null`, `status: "pending"`; settlement treats as error → HTTP 502. Admins cannot exercise invoice workflow without Fortnox credentials.
  Root cause: Strict `!result.externalId` check with no dev stub ID.
  Fix: NullProvider returns synthetic `externalId` in non-prod, or settlement accepts `pending` and stores `status: INVOICED` with null fortnox id + banner "manuell faktura".
  Effort: S

[1.5] Concurrent settlement generate — race double-settlement
  File: apps/api/src/routes/settlement.ts:67-69, 76-145
  Symptom: Two parallel POSTs while campaign is ENDED both pass pre-tx status check; both run transaction, upsert payouts, set SETTLED — duplicate audit entries; last writer wins on amounts.
  Root cause: Status guard outside transaction; no `SELECT … FOR UPDATE` on campaign row; no in-tx `WHERE status = 'ENDED'` on update.
  Fix: Move status check + campaign update into single tx with row lock: `UPDATE campaigns SET status = 'SETTLED' WHERE id = ? AND status = 'ENDED' RETURNING id`; abort if 0 rows.
  Effort: S
  Ref: feedback 03_settlement [Dubbleringsskydd — ADR on re-run policy]

[1.6] create-invoice lacks idempotency — duplicate Fortnox invoices
  File: apps/api/src/routes/settlement.ts:225-285
  Symptom: Double-click or retry on `POST /create-invoice/:payoutId` creates another Fortnox invoice when first call succeeded but client timed out; no check for existing `fortnoxInvoiceId` or `status === INVOICED`.
  Root cause: No guard before `invoiceProvider.createInvoiceFromOrder`.
  Fix: If `payout.fortnoxInvoiceId` or `status !== 'PENDING'`, return existing id; wrap in tx.
  Effort: S
  Ref: platform-audit [2.16]

[1.7] Avräkning UI aggregates all org sales — misleading vs per-campaign settlement
  File: apps/web/src/app/(fundraising)/forening/avrakning/page.tsx:57-62
        apps/api/src/routes/dashboard.ts:85-97 (no campaignId filter on salesByTeam)
  Symptom: Page picks first ACTIVE/ENDED campaign for margin label but `totalSalesOre` sums PAID orders across every campaign in org; per-team rows same cross-campaign mix.
  Root cause: Dashboard association endpoint is org-wide, not campaign-scoped.
  Fix: Pass `campaignId` query param to dashboard or use settlement by-campaign API; show campaign selector.
  Effort: M
  Ref: Scout 15 [2.x dashboard scope]

WHAT WORKS (keep)
================================================================
- Role gates on all three settlement routes (ASSOCIATION_ADMIN scoped to org; INTERNAL_ADMIN global).
- Unique index `payouts_campaign_team_unique_idx` prevents duplicate payout rows per team/campaign.
- Transaction wraps payout upserts + campaign SETTLED in one commit.
- Margin split formula matches UI estimates (`marginPercent` on campaign).
- CANCELLED/FAILED/PENDING orders excluded via PAID-only aggregation.
- Audit log fires on successful generate with status transition metadata.
- Payout schema includes fortnoxInvoiceId and PENDING/INVOICED/PAID enum ready for workflow extension.
