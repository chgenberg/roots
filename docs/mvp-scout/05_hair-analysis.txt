SCOUT 5 — Hair analysis lead flow (/haranalys, dialog, API)
================================================================
Date: 2026-05-25
Scope: PUBLIC — visitors becoming leads via håranalys wizard
Files: haranalys/page.tsx, hair-analysis-lead-dialog.tsx, hair-analysis.ts,
        hair-analysis-run.ts, packages/db/src/schema/leads.ts

SUMMARY
-------
End-to-end flow is largely wired: 8-step wizard, CSRF-protected POST
`/v1/ai/hair-analysis`, OpenAI vision with 120s abort, IP rate limit (15/24h),
lead rows in `hair_analysis_leads`, and structured results UI when JSON parses.
Images are not persisted server-side (in-memory → OpenAI only) — aligned with
integritet copy. Main MVP blockers: hidden `newsletterConsent: true` (GDPR),
weak lead dedupe (fresh idempotency UUID per submit, no email uniqueness),
generic product CTA (no mapping from AI package names to `/produkter` slugs),
and no handling for `imageValidationFailed` / `fallback` API flags.
Findings: 22 (P1:2 P2:8 P3:8 P4:4)
MVP readiness: 68/100

P1 — CRITICAL (MVP-blocking)

[1.1] Newsletter consent sent as opted-in without visible control
  File: apps/web/src/components/hair-analysis-lead-dialog.tsx:164,193,305-306
  API: apps/api/src/routes/hair-analysis.ts:102
  Schema: packages/db/src/schema/leads.ts:7 (newsletter_consent)
  Symptom: `const [newsletterConsent] = useState(true)` — fixed true, no checkbox;
  payload always `newsletterConsent: true` while integritet §3 requires explicit
  consent for marketing (Art. 6.1 a).
  Root cause: Comment “included in privacy policy” conflates analysis consent with
  newsletter opt-in.
  Fix: Separate checkbox + copy, default false; persist in draft; only send true
  when checked. Align integritet if bundled consent is intentional (legal review).
  Effort: S
  Ref: PUBLIC audit [1.2], CONVERSION_TRUST [1.2]

[1.2] `ageConfirmed: true` sent without any age gate in UI
  File: hair-analysis-lead-dialog.tsx:306; hair-analysis.ts:103
  Symptom: Client hardcodes `ageConfirmed: true`; DB stores it; no 18+ checkbox
  or copy despite composer agent 01 UX spec.
  Root cause: Field added for API/schema completeness, not wired to wizard.
  Fix: Add explicit age confirmation on gate step or remove field from contract.
  Effort: S

P2 — HIGH

[2.1] Idempotency key regenerated on every analysis attempt — weak dedupe
  File: hair-analysis-lead-dialog.tsx:290
  Symptom: `crypto.randomUUID()` inside `submitAnalysis()` — double-click or
  retry after error inserts another `hair_analysis_leads` row (email not unique).
  Root cause: Idempotency tied to submit event, not session/email.
  Fix: Stable key per wizard open (ref/state) or derive from email+day; use
  `onConflictDoNothing` / upsert on email with consent audit.
  Effort: S

[2.2] Product recommendation CTA not mapped to packages or bundle slug
  File: hair-analysis-lead-dialog.tsx:833-837; hair-analysis-run.ts:66-81
  Symptom: “Se produkterna” → `/produkter` only. AI returns “Roots Underhåll” /
  “Roots Extra Fukt” / “Roots Balanserad Rutin”; DB seed has bundle
  `complete-kit` (“Roots Complete Kit”) — no slugs for the three AI packages.
  Root cause: Marketing package names are prompt-only; produkter page lists SKUs
  (shampoo, conditioner, body-wash).
  Fix: Map `packageName` → `/produkter/complete-kit` or anchor section; or add
  three bundle records + deep links; surface recommended name in CTA query/hash.
  Effort: M

[2.3] `imageValidationFailed` from model not handled in client
  File: hair-analysis-run.ts:59-60; hair-analysis-lead-dialog.tsx:329-335
  Symptom: Model can return `{"imageValidationFailed":true,"message":"..."}` per
  prompt; client parses as ParsedAnalysis, shows empty/partial result instead of
  sending user back to photo steps with message.
  Root cause: No branch on validation flag after JSON.parse.
  Fix: Detect flag; show error; `setStep("photo-back")` with preserved email/consent.
  Effort: S

[2.4] API `fallback: true` (AI off) indistinguishable from real vision result
  File: hair-analysis.ts:115-133; hair-analysis-lead-dialog.tsx:322-335
  Symptom: 200 + static JSON when `AI_ENABLED=false` or missing key; UI shows
  same success checkmark and “Din håranalys är klar” as live analysis.
  Root cause: Client ignores `data.fallback`.
  Fix: Banner: “Förhandsgranskning — full AI-analys aktiveras snart”; optional
  disable product recommendation specificity.
  Effort: S

[2.5] No retry affordance after vision failure; 502 may leak provider text
  File: hair-analysis.ts:148-150; hair-analysis-lead-dialog.tsx:337-339
  Symptom: Error returns user to confirm with message; `throw new Error(data.error)`
  may surface `OpenAI API error: 429 ...` from server. No “Försök igen” distinct
  from re-clicking submit; no exponential backoff.
  Root cause: Single attempt; server forwards `e.message` to client.
  Fix: Sanitize 502 body for public; add retry button with same idempotency key.
  Effort: S
  Ref: AI_COACH audit [4.6]

[2.6] Session draft restores answers but not photos — confusing resume
  File: hair-analysis-lead-dialog.tsx:102-125,187-224
  Symptom: sessionStorage saves email/answers for 30 min; File objects not stored.
  User returning mid-funnel sees questions prefilled but must re-upload both images
  without explanation.
  Root cause: By design (no base64 in storage — good for privacy) but no UX copy.
  Fix: On resume, toast or step banner: “Ladda upp bilderna igen”; or reset step
  to photo-back when files missing.
  Effort: S

[2.7] “Boka samtal” on result step implies scheduling; links to `/foreningsliv`
  File: hair-analysis-lead-dialog.tsx:839-843
  Symptom: Secondary CTA after D2C hair analysis routes to association marketing,
  not booking or hair-specific contact.
  Root cause: Reused foreningsliv CTA pattern from header.
  Fix: Rename (“Läs om föreningsförsäljning”) or link `/kontakt` with subject;
  add Calendly when available.
  Effort: S
  Ref: PUBLIC [2.7]

[2.8] Lead save failure is silent — analysis still runs, no lead in CRM
  File: hair-analysis.ts:96-110
  Symptom: `catch` logs `Lead save failed` and continues to OpenAI; visitor gets
  result but ops may have no row (DB down, duplicate idempotency, etc.).
  Root cause: Best-effort insert by design.
  Fix: If insert fails on non-duplicate error, return 503 or queue lead retry;
  surface “Vi sparade din e-post för uppföljning” only when insert OK.
  Effort: M
