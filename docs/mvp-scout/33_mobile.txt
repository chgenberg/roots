================================================================
SCOUT 33 — Mobile responsiveness audit (360–414px)
================================================================
Date: 2026-05-25
Scope: All public, portal, shop, auth pages; Tailwind v4 @theme (globals.css); layout shells (marketing, auth, portal, fundraising, shop)
Viewport targets: 360px (Galaxy S8 / small Android), 375–414px (iPhone SE–Pro Max)
Roles: ALL (mobile-first audience)
References: docs/flow-audits/PUBLIC_2026-04-18_1238.txt, SELLER_2026-04-18_1245.txt,
            TEAM_LEADER_2026-04-18_1243.txt, SUPPORTER_2026-04-18_1247.txt;
            docs/mvp-scout/06_public-chat.txt, 22_shop-cart.txt

SUMMARY
-------
Read-only pass across marketing shells, auth/register flows, supporter shop/checkout, fundraising dashboards, and B2B portal. Layout grids generally stack cleanly at 360px and wide `<Table>` surfaces scroll inside `overflow-auto` wrappers as intended. MVP-blocking gaps cluster in three systemic areas: (1) global form inputs at 14px trigger iOS focus-zoom on every auth/checkout/portal form; (2) long URL copy rows in flex layouts lack `min-w-0` and can force horizontal page scroll; (3) fixed bottom chrome (shop cart bar, product CTA, chat FAB) lacks coordinated safe-area padding and content offset, so thumbs/home-indicator overlap footer links and last-fold CTAs. Header/portal hamburger controls remain under the 44×44px touch target minimum flagged in April audits.
Findings: 28 total (P1: 5, P2: 11, P3: 8, P4: 4)
MVP readiness (mobile UX): 54/100

P1 — CRITICAL (MVP-blocking on mobile)
================================================================

[1.1] Global `<Input>` at 14px triggers iOS auto-zoom on every form focus
  Files: apps/web/src/components/ui/input.tsx:10; cascades to login, registrera, checkout kassa, portal modals, fundraising settings, hair-analysis wizard.
  Symptom: On iPhone Safari, tapping any text field zooms the page ~1.1×; layout jumps; user must pinch out after each field — especially painful on multi-step `/registrera` and checkout.
  Root cause: `text-sm` (14px) on native `<input>`; Apple zooms inputs <16px.
  Fix: Change default Input to `text-base` (16px) on mobile via `text-base md:text-sm` or unconditional `text-base`; mirror in hair-analysis native `<input>` classes; add optional globals.css `@media (max-width: 767px) { input, select, textarea { font-size: 16px; } }` as belt-and-braces.
  Effort: S
  Ref: SUPPORTER [3.10] adjacent; affects ALL roles.

[1.2] Long URL copy rows force horizontal page scroll at ~360px
  Files: apps/web/src/app/(fundraising)/min-shop/page.tsx:283–291; lag/page.tsx:211–224; forening/lag/page.tsx:244–261; installningar/page.tsx:286–291 (seller shop URL block).
  Symptom: Read-only `<Input value={fullUrl}>` inside `flex gap-2` expands past viewport; body scrolls sideways; copy button may clip off-screen.
  Root cause: Flex child default `min-width: auto`; URL string sets intrinsic min-width > 360px; Input has `w-full` but sibling Button prevents shrink.
  Fix: Wrap input in `min-w-0 flex-1`; add `truncate` or stack vertically on `max-sm:flex-col`; prefer copy-only pattern (hide URL text, show “Kopiera länk” full-width).
  Effort: S
  Ref: TEAM_LEADER [2.20], SELLER [3.18] — STILL OPEN on `/lag`, `/min-shop`, `/forening/lag`.

[1.3] Shop sticky cart bar covers last content and legal footer
  Files: apps/web/src/app/(shop)/shop/[slug]/page.tsx:166,331–354; apps/web/src/app/(shop)/layout.tsx:17–41.
  Symptom: With items in cart, supporter scrolls to delivery info or footer köpvillkor/integritet links — content hidden under ~64px+ fixed bar; must scroll extra blind distance.
  Root cause: `<main>` has fixed `py-8` only; no `pb-24`/`pb-[calc(4rem+env(safe-area-inset-bottom))]` when `totalItems > 0`.
  Fix: Conditional bottom padding on main or page wrapper matching cart bar height + safe-area; or inset spacer div above footer.
  Effort: S
  Ref: SUPPORTER [3.3] partial (safe-area on bar yes; content offset no); scout 22 cart scope.

[1.4] Auth/register layout vertically centers forms — submit CTA hidden behind mobile keyboard
  Files: apps/web/src/app/(auth)/layout.tsx:17–18; apps/web/src/app/(auth)/registrera/page.tsx (multi-step, ~537 lines, step buttons use `onClick` not `<form submit>`).
  Symptom: On `/login` and `/registrera`, `flex-1 items-center justify-center` keeps card mid-screen; opening keyboard on step 2–3 pushes fields up but “Skapa konto” / “Nästa” may sit under keyboard; Enter key inconsistent (wizard uses div+onClick).
  Root cause: Vertical centering + no `items-start`/`overflow-y-auto` on small viewports; non-form step navigation.
  Fix: `@media (max-width: 767px)` switch main to `items-start pt-6 pb-8 overflow-y-auto`; wrap steps in `<form onSubmit>`; scroll focused field into view on focus.
  Effort: M
  Ref: ASSOCIATION_ONBOARDING [2.18], [3.17] — STILL OPEN.

[1.5] Dual fixed bottom chrome on product detail — chat FAB overlaps sticky CTA
  Files: apps/web/src/app/(marketing)/produkter/[slug]/page.tsx:187–197; apps/web/src/components/chat-widget.tsx:340–355; apps/web/src/app/(marketing)/layout.tsx:16.
  Symptom: On `/produkter/shampoo` etc. at 360px, user sees sticky “Beställ via din förening” bar AND chat FAB bottom-right; FAB sits on bar/CTA zone; thumb target ambiguity.
  Root cause: Independent fixed layers with no z-index/priority coordination; product sticky bar has no right padding for FAB clearance.
  Fix: Hide ChatWidget on routes with bottom sticky bars, raise FAB to `bottom-24` when sticky bar present, or merge into one bottom sheet; add safe-area to both.
  Effort: S
  Ref: PUBLIC mobile + scout 06 mobile keyboard scope.
