================================================================
SCOUT 9 — Team leader registration
================================================================
Date: 2026-05-25
Scope: TEAM_LEADER self-serve signup — `apps/web/src/app/(auth)/registrera/page.tsx` (team path), `apps/api/src/routes/auth.ts` (`POST /register/team-leader`, `GET /organizations/search`), `packages/db/src/schema/{teams,organizations}.ts`; cross-ref invite path `registrera/lagansvarig/[token]`

NOTE ON ROUTE
-------------
Scout brief references `/registrera/lagledare/` — **that route does not exist**. Team-leader self-registration lives inside the combined `/registrera` wizard (`type === "team"`). The invite-based path is `/registrera/lagansvarig/[token]` (Sprint E9, association-admin → coach claim). Both paths share role `TEAM_LEADER` and redirect target `/lag`.

SUMMARY
-------
Team-leader registration is structurally implemented (3-step form, transactional API, session cookie, welcome email, audit log, 32-char `inviteToken`), but the self-serve path is MVP-broken in practice: org search requires an authenticated session so pre-login search always fails silently; when no `ACTIVE` campaign exists on the org the API creates user+org but skips team creation yet the UI always redirects to `/lag`, producing a dead-end dashboard. The invite-claim path (`/registrera/lagansvarig/[token]`) is the only reliable onboarding route today.
Findings: 16 (P1:3 P2:5 P3:5 P4:3)
MVP readiness: 35/100

P1 — CRITICAL (blocks MVP)
================================================================

[1.1] Org search unusable before login — existing-org attach broken
  File: apps/web/src/app/(auth)/registrera/page.tsx:71-86
  File: apps/api/src/routes/auth.ts:831-835
  Symptom: Coach types föreningsnamn in step 1; dropdown stays empty. No error shown. User assumes föreningen "finns inte" and creates duplicate org via "Eller skriv föreningsnamn" or leaves org blank (server creates org named after lag).
  Root cause: `GET /v1/auth/organizations/search` returns 401 `{ error: "Ej inloggad" }` without session cookie. Client calls `fetch` without checking `res.ok`; catch/empty branch sets `orgSearchResults = []`.
  Fix: Allow anonymous org search for registration (rate-limited, min 2 chars, return id+name only) OR defer search until post-auth with clear copy; surface 401/403 in UI ("Logga in först" or "Kunde inte söka — försök igen").
  Effort: M
  Ref: ASSOCIATION_ONBOARDING [P1 org search]; SCOUT 2 [1.2]

[1.2] No active campaign → account created, team skipped, user sent to broken `/lag`
  File: apps/api/src/routes/auth.ts:645-665,700-712
  File: apps/web/src/app/(auth)/registrera/page.tsx:137-143
  File: apps/web/src/app/(fundraising)/lag/page.tsx:40-45,87-94
  File: apps/api/src/routes/dashboard.ts:225-236
  Symptom: Registration succeeds ("Registrering klar!"), auto-redirect to `/lag` after 1.5s. `/v1/dashboard/my-team` returns 404 "Inget lag hittades". UI shows generic "Kunde inte hämta lagdata" with retry — no explanation that föreningen saknar aktiv kampanj.
  Root cause: API only inserts `teams` row when `campaigns.status = 'ACTIVE'` for the org (`auth.ts:645-665`). Response includes `teamId: null` but frontend ignores it and always `router.push("/lag")`. Self-serve path with new org **never** has an active campaign at signup time.
  Fix: Return explicit flag e.g. `{ teamCreated: false, reason: "NO_ACTIVE_CAMPAIGN" }`; redirect to holding page ("Väntar på att föreningen startar kampanj") with contact föreningsadmin copy; OR block self-serve TL signup and route coaches only via `/registrera/lagansvarig/[token]`.
  Effort: M

[1.3] Server-side password policy missing on `POST /register/team-leader`
  File: apps/api/src/routes/auth.ts:563-565,578
  File: apps/web/src/app/(auth)/registrera/page.tsx:509
  Symptom: UI enforces min 8 chars; API only checks `!password` (presence). Client-side bypass or crafted request can register with 1-char password.
  Root cause: Password length validation exists on password-reset (`auth.ts:300`) and invite-claim (`association.ts:297-298`) but not on team-leader self-register. Same gap on `/register/association` and `/register/seller`.
  Fix: Shared validator: min 8, max 128; return `{ error: "Lösenord måste vara 8–128 tecken." }` before hash.
  Effort: S
  Ref: TEAM_LEADER audit [1.3]

P2 — HIGH (must fix before MVP launch)
================================================================

[2.1] Welcome email login link 404
  File: apps/api/src/lib/email/templates.ts:61
  File: apps/web/src/app/(auth)/login/page.tsx (exists)
  Symptom: Post-registration email CTA "Logga in" → `${siteUrl()}/logga-in`. No `/logga-in` route in web app; middleware and UI use `/login`.
  Root cause: Swedish URL slug in email template never wired to Next.js route.
  Fix: Change href to `/login` (or add redirect `/logga-in` → `/login`).
  Effort: S

[2.2] Frontend ignores `teamId` in registration response
  File: apps/web/src/app/(auth)/registrera/page.tsx:127-143
  Symptom: Success state and redirect identical whether or not team was created. Coach cannot tell if onboarding succeeded fully.
  Root cause: `apiFetch` typed as `{ error?: string }` only; no branch on `teamId` / `teamCreated`.
  Fix: Parse response; if `!teamId` show campaign-pending screen instead of `/lag`; if team exists show invite-link preview or deep link to `/lag/saljare`.
  Effort: S

[2.3] Duplicate org proliferation when search fails
  File: apps/api/src/routes/auth.ts:609-625
  File: apps/web/src/app/(auth)/registrera/page.tsx:390-401
  Symptom: Coach cannot find real förening (search broken) → types new name or skips org field → API inserts new `organizations` row (`type: "club"` or `"team"`) per signup.
  Root cause: Fallback org creation from `orgName`, `newOrgName`, or `teamName` with no dedup/normalization at registration time (normalization job runs async after commit).
  Fix: Fix org search first; add server-side normalized-name dedup warning or block; require explicit "Skapa ny förening" confirmation.
  Effort: M

[2.4] Two TL onboarding paths with no product guidance
  File: apps/web/src/app/(auth)/registrera/page.tsx:195-212
  File: apps/web/src/app/(auth)/registrera/lagansvarig/[token]/page.tsx
  File: apps/web/src/app/(fundraising)/forening/lag/page.tsx:101,180
  Symptom: Self-serve "Lag eller klass" on `/registrera` promises "börja sälja direkt" but requires pre-existing ACTIVE campaign. Working path is association-admin invite link `/registrera/lagansvarig/[token]` — not mentioned on self-serve flow.
  Root cause: Self-serve API shipped before campaign-first funnel; invite path (E9) is the intended production flow but marketing/register UI still advertises direct team signup.
  Fix: Self-serve copy: "Be din förening bjuda in dig" + link explanation; demote self-serve to secondary; or auto-create DRAFT campaign for new orgs (product decision).
  Effort: M

[2.5] Audit log records team entity with null id when no team created
  File: apps/api/src/routes/auth.ts:685-691
  Symptom: `auth.register.team_leader` audit row has `entityType: "team"`, `entityId: null` when signup succeeds without team — breaks downstream audit queries expecting FK.
  Root cause: `entityId: txResult.createdTeamId` without fallback.
  Fix: Use `entityType: "user"` + `entityId: userId` when team skipped; add `meta.teamCreated: false`.
  Effort: S

WHAT WORKS (invite path — out of scope but relevant)
================================================================

`/registrera/lagansvarig/[token]` + `POST /v1/association/team-invites/claim`:
  - Public GET preview (org, team, campaign names)
  - Token expiry + used-at guards

  - Session + redirect `/lag`
