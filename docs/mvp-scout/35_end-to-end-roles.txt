SUMMARY
-------
The fundraising money loop is **partially wired in the API** but **not coherent as a product story**. Registration → campaign → team invite → seller shop → checkout → PAID attribution works in dev when Klarna credentials are absent (mock “Simulera betalning” + `/confirm` marks PAID). Seller, team-leader, and association dashboards all read `customer_orders` correctly. The flywheel **breaks at the top and the tail**: INTERNAL_ADMIN KPIs and `/portal/statistik` aggregate the B2B `orders` table, not supporter `customer_orders`, so platform-wide fundraising revenue never surfaces; settlement requires `ENDED` status but no UI sets it and no UI calls settlement APIs; Fortnox invoice + `PAID` payout states are backend-only. Cross-role handoffs lack live refresh, several route names differ from the spec, and confirmation email fires only from the Klarna webhook path (not the dev/mock confirm path).

End-to-end MVP readiness: 44/100

NOTES FOR THE TEAM
------------------
1. **Two order universes** — Fundraising (`customer_orders`) and B2B club wholesale (`orders`) are separate. The fundraising flywheel is wired through `dashboard/*` for assoc/TL/seller, but `/portal/*` admin surfaces still read B2B `orders`. Fixing admin KPIs + statistik to union or prioritize `customer_orders` is the single highest-leverage integration fix.

2. **Dev happy path that works today** — Seed or manual flow: assoc registers → creates campaign on `/forening` → `/forening/lag` invite → TL claims at `/registrera/lagansvarig/{token}` → TL copies seller link → seller registers → supporter buys on `/shop/{slug}` → click mock “Simulera betalning” → `/bekraftelse` calls `/confirm` → PAID → refresh `/min-shop`, `/lag`, `/forening` to see sale. Email and admin views still fail in this path.

3. **Money loop tail is UI-empty** — Settlement backend is ~80% there but the product stops at “campaign still ACTIVE forever.” Ship: (a) REST PATCH campaign→ENDED, (b) wire `/forening/avrakning` to settlement API, (c) honest Fortnox stub for dev, (d) mark payout PAID — before calling the flywheel “complete.”

4. **Spec vs code route map** — Document for QA: förening=`/registrera?type=association`, lagledare=`/registrera/lagansvarig/[token]`, säljare=`/registrera/saljare/[token]`, seller home=`/min-shop`, internal sales CRM=`/portal/saljare`.

5. **Regression gate suggestion** — One Playwright script: assoc signup → campaign → TL invite claim → seller signup → add to cart → checkout mock pay → assert PAID on seller + team + assoc dashboards + `customer_orders` row with matching teamId/campaignId/sellerId → assert admin dashboard includes order count from `customer_orders` (after fix).
