================================================================
Date: 2026-05-25
Scope: PUBLIC (supporters) post-purchase — `apps/web/src/app/(shop)/shop/[slug]/bekraftelse/page.tsx`, `apps/web/src/app/(shop)/shop/[slug]/order/[orderId]/page.tsx`, `apps/api/src/routes/checkout.ts` (return paths, confirm, order-status, webhook email), `apps/api/src/lib/email/templates.ts` (`orderConfirmationEmail`), `apps/api/src/lib/email/index.ts` (sender)

Ref: docs/flow-audits/SUPPORTER_2026-04-18_1247.txt ([2.17]–[3.17], post-purchase), CONVERSION_TRUST_2026-04-18_1313.txt ([2.18], [4.6]), MASTER_PLAN (transaktionella mail — do not regress)

SUMMARY
-------
Post-purchase has two surfaces: a thin thank-you (`bekraftelse?order_id=`) and a richer public order-status page (`order/[orderId]`). Happy path shows total + email + link to status; email fires on Klarna webhook with branded HTML and item table. MVP blockers: confirmation email is **not** sent when status flips to PAID via the thank-you poll alone; fulfillment statuses (CONFIRMED/SHIPPED/DELIVERED) and carrier tracking are **schema/UI-only** with no write path or tracking fields; thank-you omits line items and seller/org social proof; no PDF/print save; public order APIs are unauthenticated capability URLs (UUID); email lacks explicit moms breakdown and `LegalIdentityBlock` disclosures.
Findings: 18 total (P1: 5, P2: 7, P3: 4, P4: 2)
MVP readiness: 48/100

P1 — CRITICAL (blocks MVP)
================================================================

[1.1] Order confirmation email only on webhook — not on confirm poll
  File: apps/api/src/routes/checkout.ts:355–367 (email in webhook only)
  File: apps/api/src/routes/checkout.ts:379–424 (`GET /confirm/:orderId` sets PAID, no `sendEmail`)
  Symptom: Supporter lands on thank-you; confirm upgrades PENDING→PAID if Klarna complete, but **no email** unless webhook already ran. Dev/mock Klarna or delayed webhook → paid order, no confirmation mail.
  Root cause: Duplicate payment-ack paths; email tied to webhook branch only.
  Fix: Extract `sendOrderConfirmationIfPaid(orderId)`; call from webhook and from confirm when status transitions to PAID (idempotent flag e.g. `confirmationEmailSentAt`).
  Effort: S
  Ref: SUPPORTER post-purchase baseline [4.6] — regression risk

[1.2] Fulfillment status stepper is cosmetic — no SHIPPED/DELIVERED pipeline
  File: packages/db/src/schema/customer-orders.ts:17–27 (enum includes CONFIRMED/SHIPPED/DELIVERED)
  File: apps/api/src/routes/checkout.ts (only PAID/FAILED/PENDING/DRAFT writes)
  File: apps/web/src/app/(shop)/shop/[slug]/order/[orderId]/page.tsx:35–41, 153–195
  Symptom: Supporters see five-step tracker; orders stay on **Betald** forever in production. "Skickad/Levererad" never lights up.
  Root cause: No `PATCH` (or job) to advance `customer_orders.status` past PAID (SCOUT 15 noted same gap).
  Fix: MVP minimum — `PATCH /v1/dashboard/orders/:id/status` for TEAM_LEADER/INTERNAL_ADMIN + optional auto CONFIRMED on PAID; or hide steps until backend exists.
  Effort: M
  Ref: feedback-plans/06-campaign-execution/07_logistics_packing.txt

[1.3] No shipment tracking link (schema + API + UI)
  File: packages/db/src/schema/customer-orders.ts (no tracking fields)
  File: apps/api/src/routes/checkout.ts:459–470 (`order-status` response)
  Symptom: Checklist expects carrier URL when available; nothing to store or render.
  Fix: Add `carrier`, `trackingUrl`, `shippedAt`; expose on `order-status`; CTA "Spåra paket" when set.
  Effort: M

[1.4] Public order endpoints are unauthenticated capability URLs (IDOR)
  File: apps/api/src/routes/checkout.ts:379–424, 427–475
  File: platform-audit AUDIT_2026-04-15_2324 [1.6]
  Symptom: Anyone with UUID can read masked buyer data + line items + seller name via `/v1/checkout/order-status/:orderId` and `/confirm/:orderId`. Slug in `/shop/{slug}/order/{id}` is **not** validated server-side against order's seller.
  Root cause: Guest-friendly design without signed token or email proof.
  Fix: MVP — HMAC `order_token` in Klarna confirmation URL + require on status API; or rate-limit + shorten retention messaging. Document tradeoff if deferring.
  Effort: M
  Ref: GDPR URL params OK; **link secrecy** is the issue

[1.5] Thank-you page missing line-item recap (trust at purchase moment)
  File: apps/web/src/app/(shop)/shop/[slug]/bekraftelse/page.tsx:13–18, 106–121
  Symptom: Supporter sees total only before leaving; must open email or order-status for SKU list. SUPPORTER [3.15], checkout funnel trust gap.
  Fix: Extend `GET /confirm/:orderId` with `items[]` (same join as order-status); render readonly list + frakt + "inkl. moms" on bekraftelse.
  Effort: S
