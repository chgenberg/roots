SCOUT 8 — Association registration (/registrera + API)
================================================================
Date: 2026-05-25
Scope: ASSOCIATION_ADMIN signup — `apps/web/src/app/(auth)/registrera/` (page + layout), `POST /v1/auth/register/association`, `GET /v1/auth/organizations/search`, `packages/db/src/schema/organizations.ts`, `packages/db/src/schema/users.ts`
Note: No dedicated `/registrera/forening/` route exists; association signup is the `"association"` branch inside the shared `/registrera` page.

SUMMARY
-------
Association registration is a working 3-step wizard that atomically creates org + user, sets a session cookie, fires audit + welcome email, and redirects to `/forening`. Core happy-path is shippable. MVP blockers remain: API skips contract validation (password length, email format, orgnr), duplicate orgs are not prevented, and a Redis/session failure after DB commit leaves an orphan account with a generic 500. Post-signup lands on a dashboard without a guided setup wizard.
Findings: 18 total (P1: 4, P2: 7, P3: 5, P4: 2)
MVP readiness: 62/100

P1 — CRITICAL (blocks MVP)
================================================================

[1.1] Server does not enforce password length or complexity on association register
  File: apps/api/src/routes/auth.ts:446-448,461; packages/contracts/src/auth.ts:20-33 (unused)
  Symptom: Client disables submit when `password.length < 8`, but API accepts any non-empty password (e.g. `"1"` via curl/Postman). `RegisterAssociationSchema` defines `.min(8)` but is never parsed in the route.
  Root cause: Manual field presence check instead of Zod contract; no parity with `change-password` (min 8 at auth.ts:298-302).
  Fix: Parse body with `RegisterAssociationSchema.safeParse()`; return 400 with field errors. Optionally add complexity rule matching product policy.
  Effort: S
  Ref audit: ASSOCIATION [3.2] — STILL UNRESOLVED

[1.2] Session creation failure after successful DB commit → orphan account
  File: apps/api/src/routes/auth.ts:463-507,535-537; apps/api/src/lib/session.ts:41-43
  Symptom: If `createSession` throws (Redis down in production), transaction already committed org + user. Handler returns generic 500 `"Registreringen misslyckades."` with no session cookie. User cannot retry with same email (409) and may not know to use login.
  Root cause: Session created outside tx with no rollback/compensation; login path handles this with 503 (`auth.ts:163-167`) but register does not.
  Fix: Wrap `createSession` in try/catch; on failure return 503 with copy "Kontot skapades — logga in" OR delete org+user in compensating tx; align with login error handling.
  Effort: M
  Ref audit: NEW (reliability gap)

[1.3] No duplicate-organization prevention for association signup
  File: apps/api/src/routes/auth.ts:464-472; packages/db/src/schema/organizations.ts:35-36
  Symptom: Each association registration inserts a new org row. Same förening can register twice (same name or orgNumber). No unique index on `org_number`; no name normalization check. Sales lead API dedupes by orgNumber (`sales.ts:114-123`) but register path does not.
  Root cause: Association flow bypasses org search entirely; free-text `orgName` with optional `orgNumber` stored as-is.
  Fix: If `orgNumber` provided, reject 409 when org exists; optional pre-submit search by normalized name; add unique partial index on `org_number` where not null.
  Effort: M
  Ref audit: ASSOCIATION [3.4], [3.5] — STILL UNRESOLVED (worse: no dedup at all)

[1.4] No server-side email format validation
  File: apps/api/src/routes/auth.ts:446-448,478
  Symptom: Malformed strings (e.g. `"not-an-email"`) pass API validation if truthy; stored in DB; welcome email may fail silently.
  Root cause: No `.email()` check; contract schema unused.
  Fix: Enforce via `RegisterAssociationSchema` (already has `z.string().email()`).
  Effort: S
  Ref audit: ASSOCIATION [3.2] — STILL UNRESOLVED (partial)

[2.1] Post-signup redirect skips setup wizard — post-login desert
  File: apps/web/src/app/(auth)/registrera/page.tsx:137-144; apps/web/src/app/(fundraising)/forening/page.tsx:187-201
  Symptom: Success → 1.5s delay → `/forening` KPI dashboard. No "steg 1 av 4", no checklist (kampanj → lag → säljare). New admin sees "Ingen aktiv kampanj" with a button but no guided first-run flow.
  Root cause: Product never shipped onboarding wizard; audit finding [2.1] still applies.

  Effort: M
  Ref audit: ASSOCIATION [2.1]–[2.3] — STILL UNRESOLVED (campaign modal added in Sprint E9 — partial)

[2.2] Organisationsnummer not validated (Swedish format)
  File: apps/web/src/app/(auth)/registrera/page.tsx:298-304; apps/api/src/routes/auth.ts:468
  Symptom: User can enter `"abc"` or wrong digit count; stored in `organizations.org_number` without checksum/pattern.
  Root cause: Optional field with placeholder only; register API lacks regex used elsewhere in `sales.ts:106`.
  Fix: Client mask/validate `^\d{6}-?\d{4}$` + Luhn if required; server reject invalid with 400.
  Effort: S
  Ref audit: ASSOCIATION [3.4], [3.5] — STILL UNRESOLVED

[2.3] `RegisterAssociationSchema` defined but unused in API route
  File: packages/contracts/src/auth.ts:20-33; apps/api/src/routes/auth.ts:423-448
  Symptom: Contract drift — web sends ad-hoc JSON; server uses `any` + manual checks. Future field additions won't be validated consistently.
  Root cause: Route predates contract wiring.
  Fix: Import and `safeParse` in `/register/association` (and team-leader for parity).
  Effort: S

[2.4] No registration rate limiting (abuse / org spam)
  File: apps/api/src/routes/auth.ts:423-539
  Symptom: Unlike `/login` (IP+email rate limit at auth.ts:106-111), register endpoints accept unlimited POSTs — enables org/user table spam and email bombing via welcome template.
  Root cause: Rate limit only on login.
  Fix: Add `registerRateLimit(ip)` similar to login; cap e.g. 5/hour/IP.
  Effort: S

[2.5] Auth layout vertical centering hides mobile submit behind keyboard
  File: apps/web/src/app/(auth)/layout.tsx:17; apps/web/src/app/(auth)/registrera/page.tsx:507-520
  Symptom: `main` uses `items-center justify-center`; long step-3 form on 375px — "Skapa konto" may sit below fold or under iOS keyboard. No sticky footer CTA.
  Root cause: Centered flex layout without scroll padding.
  Fix: `items-start sm:items-center`, `scroll-padding-bottom`, sticky bottom bar on step 3.
  Effort: S
  Ref audit: ASSOCIATION [2.18] — STILL UNRESOLVED

[2.6] Wizard uses click handlers, not `<form>` — Enter/autofill submit broken
  File: apps/web/src/app/(auth)/registrera/page.tsx:324-331,466-473,507-520
  Symptom: Enter key does not advance steps or submit on mobile keyboards; password managers may not offer save-password flow reliably.
  Root cause: `<Button onClick>` instead of `<form onSubmit>`.
  Fix: Wrap each step in `<form onSubmit={preventDefault; next/submit}>`.
  Effort: S
  Ref audit: ASSOCIATION [3.17] — STILL UNRESOLVED

[2.7] Postnummer/ort grid cramped on mobile
  File: apps/web/src/app/(auth)/registrera/page.tsx:446-465
  Symptom: `grid-cols-2` at all breakpoints — tight inputs on 375px.
  Fix: `grid-cols-1 sm:grid-cols-2`.
  Effort: S
  Ref audit: ASSOCIATION [3.16] — STILL UNRESOLVED
