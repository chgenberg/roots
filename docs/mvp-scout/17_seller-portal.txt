SCOUT 17 — Seller portal (min shop, stats, share, profile)
================================================================
Date: 2026-05-25
Scope: SELLER role — `apps/web/src/app/(portal)/portal/page.tsx` (SELLER branch), `apps/web/src/app/(fundraising)/min-shop/`, `apps/web/src/app/(fundraising)/installningar/` (profil surrogate), `apps/api/src/routes/sharing.ts`, `apps/api/src/routes/portal.ts` (seller stats guard), `apps/api/src/routes/dashboard.ts` (`GET /seller`), `packages/db/src/schema/sellers.ts`
Note: Scout brief paths `/portal/min-shop`, `/portal/dela`, `/portal/profil` **do not exist**. Individual sellers live in the `(fundraising)` shell: `/min-shop`, `/min-shop/bestallningar`, `/installningar`. Login redirects SELLER → `/min-shop` (`login/page.tsx:49-50`). `/portal/*` is for CLUB + internal SALES_* + INTERNAL_ADMIN only (`portal.ts:31-32,70-74`).

Ref: docs/flow-audits/SELLER_2026-04-18_1245.txt, MASTER_PLAN Fas 6 (publicAlias, hideFromLeaderboard, personalMessage)

SUMMARY
-------
The seller “portal” is effectively `/min-shop` plus read-only `/installningar`. Core loop works: authenticated seller loads `GET /v1/dashboard/seller`, sees sales KPIs, copies shop URL, generates QR, uses six client-side share templates, and opens live `/shop/[slug]`. MVP blockers: no seller self-service profile edit (schema fields exist but no API/UI), public shop ignores `publicAlias`/`personalMessage`, dashboard stats contradict recent orders (PAID-only totals vs all-status feed), `first_sale` milestone “Nästa” is nonsense for zero-sale sellers, team ranking never shown to the seller, and `portal/page.tsx` has no SELLER branch (wrong admin shell if a seller hits `/portal`).
Findings: 20 total (P1: 5, P2: 8, P3: 5, P4: 2)
MVP readiness: 56/100

[1.3] Dashboard stats contradict "Senaste beställningar"
  File: apps/api/src/routes/dashboard.ts:599-610 vs 612-616, 639-655
  File: apps/web/src/app/(fundraising)/min-shop/page.tsx:152-165 vs 330-381
  Symptom: "Sålt" / "Beställningar" KPIs count **PAID** orders only; `orders` array includes **all statuses** (PENDING, etc.). Seller sees e.g. "0 beställningar" but a pending row in the feed, or inflated feed vs KPI.

  Fix: Filter feed to PAID only, OR add unpaid badge + separate "Väntar på betalning" section; align KPI labels.
  Effort: S
  Ref audit: SELLER [1.2] — STILL UNRESOLVED

[1.4] `first_sale` milestone "Nästa" shows nonsense at zero sales
  File: apps/api/src/lib/milestones.ts:56-62, 164-215
  File: apps/web/src/app/(fundraising)/min-shop/page.tsx:248-255
  Symptom: New seller with 0 PAID orders sees e.g. "Nästa: Första försäljningen! 0 kr kvar" because `first_sale` has `thresholdOre: 1` and `getNextMilestone` treats it as öre gap without special-case (unlike `halfway` / `goal_reached`).

  Fix: Special-case `first_sale` when `orderCount === 0`; skip öre math.

  Ref audit: SELLER [1.3] — STILL UNRESOLVED

[1.5] No SELLER branch in `portal/page.tsx` — wrong dashboard if route hit
