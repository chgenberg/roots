SUMMARY
-------
Sprint E4 largely fixed the April audit’s broken field mapping and removed hardcoded demo KPIs
from statistik/page.tsx — empty states and real API wiring now work for INTERNAL_ADMIN and
SALES_ADMIN. MVP-blocking gaps remain: /statistics aggregates only B2B `orders` while

P1 — CRITICAL (blocks MVP)

[1.1] /statistics ignores customer_orders — platform KPIs miss fundraising revenue
  File: apps/api/src/routes/portal.ts:1143-1271
        packages/db/src/schema/customer-orders.ts (customerOrders, customerOrderLines)
        apps/api/src/routes/portal.ts:564-609 (clubs endpoint unions B2C+B2B)
        packages/db/src/seed-demo.ts:695 (comment: association dashboard reads customer_orders)
  Symptom: INTERNAL_ADMIN “KPI & Statistik” shows near-zero revenue on a seeded/demo platform
  where supporter checkout (customer_orders PAID) is the primary revenue stream. Top products,
  monthly charts, and 30-day KPIs all query `orders` + `order_lines` only.
  Root cause: Statistics endpoint predates B2C fundraising schema; /clubs was later patched to
  union both tables but /statistics was not.
  Fix: Mirror clubs aggregate pattern — union PAID customer_orders with orders (respect
  orderScope), join customer_order_lines for top products; or expose separate B2C/B2B series
  with clear labels. Align seed so demo statistik page shows non-empty charts after db:seed:demo.
  Effort: L
  Ref audit: INTERNAL_ADMIN [1.9]/[3.12]; MASTER_PLAN Fas 1 statistics

[1.2] SALES_REP nav links to /portal/statistik but API returns 403 — silent failure
  File: apps/web/src/app/(portal)/portal/layout.tsx:49-56 (SALES_NAV includes statistik)
        apps/api/src/routes/portal.ts:1124-1128 (SALES_REP → 403)
        apps/web/src/app/(portal)/portal/statistik/page.tsx:140-143 (catch swallows error)
  Symptom: Sales rep opens “Statistik” from sidebar; page renders with em-dash KPIs and
  “Ingen omsättningshistorik ännu” / “Inga ordrar registrerade ännu” — reads as empty tenant,
  not “you lack permission”. Comment in API says stats live on /pipeline but nav still points here.
  Root cause: Intentional API guard without matching nav removal or dedicated sales stats view.
  Fix: Remove statistik from SALES_NAV and link to /portal/pipeline (or build rep-scoped stats
  endpoint); on 403 show explicit “Statistik finns under Pipeline” CTA instead of empty-state copy.
  Effort: S
  Ref audit: SALES_REP [2.5]; AI_COACH [1.10] (SELLER misrouted to admin nav — related pattern)

[1.3] isDemo returned by API but never surfaced — trust gap on empty vs live data

P2 — HIGH (must fix before MVP launch)

[2.1] “Senaste 12 mån” chart shows oldest 12 months, not latest
  File: apps/api/src/routes/portal.ts:1151-1153
        apps/web/src/app/(portal)/portal/statistik/page.tsx:204-206
  Symptom: Org with >12 months of orders sees ancient months in chart while recent months drop
  off; badge text contradicts data.
  Root cause: orderBy month ASC + limit 12 without DESC subquery or date floor.
  Fix: Filter createdAt >= now()-12 months, orderBy DESC, reverse for chart left-to-right; or
  generate zero-filled last-12-month series in SQL.
  Effort: S

[2.2] /statistics counts all order statuses; /income counts PAID only — conflicting numbers
  File: apps/api/src/routes/portal.ts:1147-1148 vs 1335-1337
        apps/web/src/app/(portal)/portal/intakter/page.tsx (club-facing PAID view)
  Symptom: Same org sees higher “Total omsättning (30d)” on statistik than “Intäkter” on
  intakter; INTERNAL_ADMIN cannot reconcile without reading source code.
  Root cause: statistics includes PENDING/CANCELLED B2B orders; income filters invoiceStatus=PAID.
  Fix: Document in UI tooltips; align statistics KPI to PAID (or split “Bokfört” vs “Totalt”);
  consider filtering customer_orders to status=PAID when B2C is added.
  Effort: M
  Ref audit: INTERNAL_ADMIN [3.12]

[2.3] No statisticsResponseSchema validation on client — drift fails silently
  File: apps/web/src/app/(portal)/portal/statistik/page.tsx:72-95 (inline type, no schema)
        apps/web/src/app/(portal)/portal/intakter/page.tsx:48 (uses incomeResponseSchema)
        packages/contracts/src/portal.ts:113-126
  Symptom: API shape regression (e.g. rename kpis field) renders empty charts without console
  error in production; intakter page would throw on drift.
  Root cause: statistik fetch predates portalFetch schema option adoption.
  Fix: portalFetch("/statistics", { schema: statisticsResponseSchema }).
  Effort: S
  Ref audit: MASTER_PLAN Fas 0 snapshot tests (API side covered; UI not)

[2.4] KPI “Aktiva medlemmar (30d)” mislabeled — counts order-placing users, not members
  File: apps/api/src/routes/portal.ts:1193 (count(distinct orders.userId))
        apps/web/src/app/(portal)/portal/statistik/page.tsx:57-60,128-131
  Symptom: Card label implies org membership activity; value is distinct B2B order authors in
  30 days (often 1 club admin). Misleading for ops and club admins.
  Root cause: Reused order aggregate for a member metric; no sellers/customer_orders activity.
  Fix: Rename to “Unika beställare (30d)” or compute from users.lastLoginAt / customer_orders
  buyer count when B2C wired.
  Effort: S

[2.5] payouts schema unused in statistics — no payout/settlement reporting

[2.6] API error states indistinguishable from empty tenant
  File: apps/web/src/app/(portal)/portal/statistik/page.tsx:140-143

[2.7] Mobile chart layout — 12 equal flex columns without min-width or scroll
  File: apps/web/src/app/(portal)/portal/statistik/page.tsx:210-233,296-321

  revenue “X.Xk” labels crowd above bars.
  Root cause: Pure CSS flex bar chart with flex-1 per bucket, no responsive breakpoint.
  Fix: overflow-x-auto wrapper with min-w-[480px] chart area; or reduce to 6 months on sm;

  Effort: S

DATA MODEL NOTES (schema scope)
-------------------------------
- orders + order_lines: B2B club wholesale (orgId, userId, invoiceStatus) — sole source for /statistics today.
- customer_orders + customer_order_lines: B2C supporter checkout (sellerId, campaignId, status PAID) — primary fundraising revenue; NOT in /statistics.
- payouts: per campaign+team settlement (totalSalesOre, teamShareOre, status) — NOT queried by /statistics.
