Sprint E9–E12 shipped a usable `/forening` shell: campaign create modal, team-invite flow, KPI dashboard, per-team goals, and read-only avräkning estimates. Briefed `/portal/*` paths do not exist for this role; `/portal/saljare` is internal sales staff only.

P1 — CRITICAL (MVP blockers)

[1.1] No leveranser surface for association admin — cannot see or fulfill org orders
  File: apps/web/src/app/(fundraising)/layout.tsx:90-97 (nav has no leveranser)
        apps/web/src/app/(fundraising)/lag/bestallningar/page.tsx (team-scoped only)
        apps/api/src/routes/dashboard.ts:49-132 (association dashboard has no orders[])
  Symptom: Föreningsadmin has no order list, filters, detail dialog, or CSV export. Team leaders use `/lag/bestallningar`; assoc admin middleware allows `/lag` but `GET /v1/dashboard/my-team` returns 404 (not a leader).
  Root cause: Org-wide customer-order read path never built for ASSOCIATION_ADMIN despite RBAC on single-order detail (dashboard.ts:714-716).
  Fix: Add `/forening/leveranser` + `GET /v1/dashboard/association/orders` (org + optional campaign filter); reuse OrderDetailDialog + orders-csv.
  Effort: L

[1.2] No API to update customer order delivery status (SHIPPED/DELIVERED)
  File: packages/contracts/src/campaigns.ts:60-70 (status enum includes SHIPPED/DELIVERED)
        apps/api/src/routes/*.ts (no PATCH for customer_orders status)
  Symptom: Even team-leader order page is read-only for fulfillment; assoc admin cannot mark bulk shipment progress.
  Root cause: Status transitions only from payment webhooks/checkout; no operator workflow.
  Fix: `PATCH /v1/dashboard/orders/:id/status` with RBAC (TEAM_LEADER own team, ASSOCIATION_ADMIN org, INTERNAL_ADMIN); audit log.
  Effort: M

[1.3] Avräkning UI disconnected from settlement + payouts — no real payout status
  File: apps/web/src/app/(fundraising)/forening/avrakning/page.tsx (entire file — only `/v1/dashboard/association`)
        apps/api/src/routes/settlement.ts:167-223 (`GET /by-campaign/:id` returns payouts with status)
        packages/db/src/schema/payouts.ts:15-19 (PENDING/INVOICED/PAID)
  Symptom: Page shows live margin math on PAID orders, not persisted payout rows. Admins cannot see PENDING/INVOICED/PAID, Fortnox id, or trigger settlement.
  Root cause: Settlement API shipped without frontend wiring (feedback-plans/08-ecommerce-integration/03_settlement_and_payouts.txt).
  Fix: Campaign picker → fetch settlement by campaign; table per team with status badges; "Generera avräkning" → POST generate (with confirm modal).
  Effort: M

[1.4] Cannot end campaign — blocks settlement pipeline
  File: apps/api/src/routes/settlement.ts:67-69 (requires `campaign.status === "ENDED"`)
        apps/api/src/trpc/routers/campaigns.ts:137-176 (update/activate exist)
        apps/web/src/app/(fundraising)/forening/ (no end-campaign control)
  Symptom: Admin creates ACTIVE campaigns but has no UI/API REST path to set ENDED. Settlement always 400 until manual DB/tRPC intervention.
  Root cause: Lifecycle mutations only in unused tRPC router; web never calls them.
  Fix: REST `PATCH /v1/association/campaigns/:id/status` or wire tRPC; "Avsluta kampanj" on dashboard with consequences copy (shops close).
  Effort: M

[1.5] No campaign product assortment — shops may show wrong catalog

[1.6] Dashboard aggregates all campaigns — misleading goal progress and leaderboard
  File: apps/api/src/routes/dashboard.ts:64-98,109-127

[1.7] Team goal PATCH omits CSRF — fails in production
