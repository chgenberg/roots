SUMMARY
-------
Fas 4 domain/sender unification is largely done in code: transactional HTML templates use
`NEXT_PUBLIC_SITE_URL`/`SITE_URL` (default `https://roots.se`), and Resend defaults to
`Roots <hej@roots.se>`. MVP-blocking gaps remain: every welcome email CTA links to
non-existent `/logga-in` (live login is `/login`), milestone and campaign-start templates are
defined but never sent, settlement has no email path, and email footers omit full LegalIdentity
(org.nr, postal address) required for trust and deliverability. Production can also boot without
`RESEND_API_KEY` and silently drop all transactional mail via MockEmailSender.
Findings: 20 total (P1: 4, P2: 8, P3: 5, P4: 3)
MVP readiness: 58/100

P1 — CRITICAL (MVP-blocking)
================================================================

[1.1] Welcome email login CTA points to `/logga-in` — 404
  File: apps/api/src/lib/email/templates.ts:61
        apps/web/src/app/(auth)/login/page.tsx (route is `/login`)
  Symptom: All four welcome-email triggers (association, team leader, seller×2) send button "Logga in" → `{siteUrl}/logga-in`. No `/logga-in` route or redirect in web app.
  Root cause: Swedish slug never wired; cross-referenced unresolved in Scout 7 [1.1] and Scout 10.
  Fix: Change href to `/login` OR add permanent redirect `/logga-in` → `/login` in next.config.
  Effort: S

[1.2] Production can run without real email delivery
  File: apps/api/src/lib/email/index.ts:15-24
        apps/api/src/lib/validate-env.ts:66-68
  Symptom: Missing `RESEND_API_KEY` selects MockEmailSender; returns `{ success: true }` locally. Prod only logs a startup warning — registration and order confirmations appear to succeed in API but never reach recipients.
  Root cause: RESEND listed as RECOMMENDED not REQUIRED.
  Fix: Fail boot in production if RESEND_API_KEY unset (or if transactional email flag enabled); alert in ops runbook.
  Effort: S

[1.3] Email footer missing mandatory LegalIdentity fields
  File: apps/api/src/lib/email/templates.ts:33-35
        apps/web/src/lib/legal-identity.ts:13-33
  Symptom: Footer shows company name + site + email only. Web checkout/footer/JSON-LD use full address, org.nr, VAT. Email recipients (especially order confirmation = contract receipt) see incomplete sender identity — trust fracture + EU marketing/company-ID expectations.
  Root cause: `wrap()` hardcodes minimal footer; no shared legal module in API package.
  Fix: Extract legal constants to `@roots/shared` or duplicate minimal block in API; footer = legalName, orgNumber, formatAddressSingleLine(), hej@roots.se, roots.se link.
  Effort: S
  Ref audit: CONVERSION_TRUST [1.15] partial fix (domain OK; footer still thin)

[1.4] Milestone emails never sent — gamification loop broken
  File: apps/api/src/lib/email/templates.ts:113-132
        apps/api/src/lib/communication-templates.ts:88-105
  Symptom: HTML `milestoneEmail` and plain `getMilestoneTemplate` exist; no route/job calls `getEmailSender()` for milestones after checkout or campaign progress.
  Root cause: MASTER_PLAN Fas 5 item never implemented; CONVERSION_TRUST [2.12] still open.
  Fix: On checkout webhook after PAID, compute team cumulative sales vs thresholds; fan-out to team leader + sellers via `milestoneEmail` (dedupe per threshold).
  Effort: M
  Note: Defer only if product explicitly drops milestone email for MVP; currently templates imply committed feature.

P2 — HIGH
================================================================

[2.1] Order confirmation email only on Klarna webhook — no fallback
  File: apps/api/src/routes/checkout.ts:331-368,379-425
  Symptom: Email fires inside webhook when order transitions to PAID. Polling endpoint `/confirm/:orderId` can also mark PAID but never sends confirmation. Missed/delayed webhook = supporter gets no receipt email.
  Fix: Extract `sendOrderConfirmation(orderId)`; call from webhook and from confirm path when status flips to PAID (idempotent flag on order row e.g. `confirmationEmailSentAt`).
  Effort: M

[2.2] Settlement / payout notifications absent
  File: apps/api/src/routes/settlement.ts (no email imports)
  Symptom: Campaign settlement creates payout rows and Fortnox invoices but no email to association admin or team leader when payout is ready/paid.
  Fix: Add `settlementCompleteEmail()` template; trigger after successful settlement transaction with summary + link to `/forening/avrakning` or portal intäkter.
  Effort: M

[2.3] Campaign-start template never wired to outbound mail
  File: apps/api/src/lib/communication-templates.ts:64-86
        apps/api/src/trpc/routers/campaigns.ts:160-176
        apps/api/src/routes/association.ts:462-496
  Symptom: Creating or activating a campaign does not email association admin with dates/goals despite ready plain-text template.
  Fix: On `POST /association/campaigns` or `campaigns.activate`, send HTML version via `getEmailSender()` to org admin contact emails.
  Effort: M

[2.4] communication-templates SITE_URL default inconsistent with transactional templates
  File: apps/api/src/lib/communication-templates.ts:1
  Symptom: Invite/share URLs default to `http://localhost:3000` when env missing; `templates.ts` defaults to `https://roots.se`. Staging misconfig yields wrong links in SMS/email copy returned by `/v1/sharing/*`.
  Fix: Align default to `https://roots.se`; reuse shared `siteUrl()` helper from email module.
  Effort: S

[2.5] Invite/share templates are plain text only — never sent via Resend
  File: apps/api/src/routes/sharing.ts:30-94
  Symptom: API returns JSON `{ email: { subject, body } }` for manual copy-paste; no automatic send, no HTML wrapper/branding. Coaches must paste into own mail client — inconsistent with welcome/order transactional quality.
  Fix: Optional `POST /sharing/send-invite` with rate limit + HTML template; or document as intentional MVP manual flow.
  Effort: M

[2.6] Transactional emails lack plain-text multipart
  File: apps/api/src/lib/email/templates.ts (html only)
        apps/api/src/lib/email/resend-sender.ts:31-32
  Symptom: Resend accepts `text` but welcome/order/milestone never set it. Hurts spam scoring and some clients that prefer text/plain.
  Fix: Generate stripped text alongside `wrap()` HTML for each template.
  Effort: S

[2.7] Unescaped user names in HTML templates
  File: apps/api/src/lib/email/templates.ts:52-54,91
  Symptom: `${name}`, `${params.customerName}` interpolated raw into HTML. Malicious or accidental `<>` in display name breaks layout or enables HTML injection in email clients.
  Fix: HTML-escape helper for all dynamic fields.
  Effort: S

[2.8] Order confirmation with missing seller slug
  File: apps/api/src/routes/checkout.ts:349-364
  Symptom: `shopSlug: seller?.shopSlug || ""` produces broken order-status URL if seller join fails.
  Fix: Guard send — skip CTA or use order-status API link `/shop/_/${orderId}` fallback; log warning.
  Effort: S
