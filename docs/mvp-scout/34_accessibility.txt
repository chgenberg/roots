SUMMARY
-------
Roots has a solid accessibility foundation — `lang="sv"`, a global skip link, Radix
dialogs with focus trap/ESC, `:focus-visible` rings in globals.css, and partial
`prefers-reduced-motion` handling. However, several WCAG AA blockers remain for MVP:
the skip link only lands on marketing pages; auth flows have no `<h1>`; hidden UI
(chat panel, mobile nav, portal sidebar) stays in the keyboard tab order; AI chat
surfaces lack `aria-live` for streamed messages; the hair-analysis wizard has six
unlabeled `<select>` controls; and contrast fails on hero subcopy and 10px disclaimers.
Findings: 28 total (P1: 8, P2: 11, P3: 6, P4: 3)
MVP readiness: 61/100

P1 — CRITICAL (blocks MVP / legal AA)
================================================================

[1.1] Skip-to-content link broken outside marketing shell
  File: apps/web/src/app/layout.tsx:79-84; apps/web/src/app/(marketing)/layout.tsx:14
  Symptom: "Hoppa till innehåll" is global, but `id="main-content"` exists only on
           `(marketing)/layout.tsx`. On `/login`, `/portal/*`, `/shop/*`, `/forening`,
           `/min-shop`, etc., activating the skip link does nothing useful.
  Root cause: Other route-group layouts use `<main>` without the shared id.
  Fix: Add `id="main-content"` to `<main>` in `(auth)/layout.tsx`, `(portal)/portal/layout.tsx`,
       `(fundraising)/layout.tsx`, and shop pages that define their own `<main>`; or move
       the id to a shared wrapper used by every layout.
  Effort: S
  WCAG: 2.4.1 Bypass Blocks (A)

[1.2] Auth pages have no document `<h1>` — CardTitle renders a `<div>`
  File: apps/web/src/components/ui/card.tsx:25-28
  File: apps/web/src/app/(auth)/login/page.tsx:64; registrera/page.tsx:170,262;
        registrera/saljare/[token]/page.tsx:95; registrera/lagansvarig/[token]/page.tsx:190
  Symptom: Screen readers and heading navigation skip the primary page title on every
           auth/registration screen ("Logga in", "Kom igång med Roots", etc.).
  Root cause: `CardTitle` is a styled `<div>`, not a heading element.
  Fix: Change `CardTitle` to render `h1` (or accept `asChild`/level prop); ensure one
       h1 per auth page. Prefer `DialogTitle`-style polymorphism if cards used as subsections elsewhere.
  Effort: S
  WCAG: 1.3.1 Info and Relationships (A), 2.4.6 Headings and Labels (AA)

[1.3] Site search dialog missing accessible name (no DialogTitle)
  File: apps/web/src/components/search-dialog.tsx:151-167
  Symptom: Radix DialogContent without DialogTitle triggers console warning and leaves
           the modal unnamed for assistive tech ("dialog" with no label).
  Root cause: SearchDialog imports only `DialogContent`; no `DialogTitle` or visually hidden title.
  Fix: Add `<DialogTitle className="sr-only">Sök på Roots</DialogTitle>` (or visible title).
  Effort: S
  WCAG: 4.1.2 Name, Role, Value (A)

[1.4] Closed chat panel remains in keyboard tab order
  File: apps/web/src/components/chat-widget.tsx:236-337
  Symptom: When chat is closed (`opacity-0 pointer-events-none`), focus can still tab
           into textarea, send, stop, and close buttons inside the off-screen dialog.
  Root cause: Panel stays mounted without `hidden`, `inert`, `aria-hidden`, or `tabIndex=-1` on descendants.
  Fix: When `!open`, add `hidden`/`inert`/`aria-hidden="true"` to the dialog container, or
       conditionally unmount panel content; return focus to floating trigger on close.
  Effort: S
  WCAG: 2.1.1 Keyboard (A), 2.4.3 Focus Order (A)

[1.5] Mobile marketing nav overlay focusable while visually hidden
  File: apps/web/src/components/header.tsx:196-272
  Symptom: Full-screen mobile menu uses `opacity-0 pointer-events-none` when closed but
           remains in DOM; Tab reaches nav links, search, and CTAs while menu appears closed.
  Root cause: No `inert`/`aria-hidden`/`hidden` when `menuOpen === false`; no focus trap when open.
  Fix: Toggle `inert` + `aria-hidden` on overlay when closed; trap focus + ESC when open; restore focus to burger.
  Effort: M
  WCAG: 2.1.1, 2.4.3

[1.6] Portal sidebar off-screen links still tabbable on mobile
  File: apps/web/src/app/(portal)/portal/layout.tsx:156-217
  Symptom: On viewports `< lg`, sidebar is `-translate-x-full` when closed but nav links,
           logout, and help remain reachable via keyboard.
  Root cause: Aside always rendered; only CSS transform hides it — no `inert`/`aria-hidden`.
  Fix: Set `inert={!sidebarOpen}` on aside for mobile, or `hidden lg:flex` pattern; trap focus when open.
  Effort: M
  WCAG: 2.1.1, 2.4.3

[1.7] Hair-analysis wizard: six `<select>` fields not programmatically labeled
  File: apps/web/src/components/hair-analysis-lead-dialog.tsx:567-648
  Symptom: `<Label>` text is visual only — no `htmlFor`/`id` pairing on wash frequency,
           hair type, scalp, heat tools, chemical treatment, swim frequency selects.
  Root cause: Label component rendered adjacent without association; Radix Label needs `htmlFor`.
  Fix: Add unique `id` per select and `htmlFor` on each Label (mirror portal/fakturor pattern).
  Effort: S
  WCAG: 1.3.1, 3.3.2 Labels or Instructions (A), 4.1.2

[1.8] AI chat messages not announced — missing aria-live region
  File: apps/web/src/components/chat-widget.tsx:267-297
  File: apps/web/src/app/(portal)/portal/ai/page.tsx:294-337
  Symptom: New assistant messages (including streamed tokens) appear silently; screen-reader
           users must manually find the message list after send.
  Root cause: Message container is a plain `<div>` with no `aria-live`/`aria-relevant`.
  Fix: Wrap message list in `aria-live="polite"` + `aria-atomic="false"` region; for streaming,
       announce completion or use live region on latest assistant bubble.
  Effort: S
  WCAG: 4.1.3 Status Messages (AA)

P2 — HIGH (must fix before MVP launch)
================================================================

[2.1] Hero subcopy contrast fails WCAG AA on photo background
  File: apps/web/src/components/sections/hero.tsx:43
  File: apps/web/src/components/sections/hero-lead.tsx:25
  Symptom: `text-white/70` (~rgba(255,255,255,0.7)) over darkened photo reads below 4.5:1
           on typical hero luminance; secondary CTA same issue.
  Fix: Use `text-white/90` or solid `#F1EBE2`; add semi-opaque text backdrop if needed.
  Effort: S
  WCAG: 1.4.3 Contrast (Minimum) (AA)

[2.2] 10px disclaimers at 60% muted opacity fail contrast
  File: apps/web/src/components/chat-widget.tsx:333
  File: apps/web/src/app/(portal)/portal/ai/page.tsx:372
  Symptom: `text-[10px] text-muted-foreground/60` is below 4.5:1 and below readable size.
  Fix: Minimum `text-xs` (12px) at full `text-muted-foreground`; verify dark mode (#B2A491 on #221F1B).
  Effort: S
  WCAG: 1.4.3, 1.4.4 Resize Text (AA)

[2.3] Checkout delivery choice not exposed as radio group
  File: apps/web/src/app/(shop)/shop/[slug]/kassa/page.tsx:296-328
  Symptom: Samleverans vs Hemleverans are `<button type="button">` tiles with no
           `role="radio"`, `aria-pressed`, or `radiogroup` — state change invisible to SR.
  Fix: Use `<fieldset>` + `<legend>` + native radios, or buttons with `role="radiogroup"` + `aria-checked`.
  Effort: S
  WCAG: 4.1.2, 1.3.1

[2.4] Hair-analysis progress bar not accessible
  File: apps/web/src/components/hair-analysis-lead-dialog.tsx:128-151
  Symptom: Step progress is visual-only `<div>` with width style; no `role="progressbar"`,
           `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, or step change announcement.
  Fix: Add progressbar semantics; optionally `aria-live="polite"` on step label when step changes.
  Effort: S
  WCAG: 4.1.2, 1.3.1

[2.5] Hero primary CTA pulse animation ignores reduced motion
  File: apps/web/src/components/sections/hero-lead.tsx:16
  Symptom: Custom `animate-[pulse-shadow-light_…]` not listed in globals.css reduced-motion block
           (only `.animate-subtle-pulse`, `.animate-float`, `.animate-spin-slow`).
  Fix: Add `motion-reduce:animate-none` on pulse span or extend `@media (prefers-reduced-motion)`.
  Effort: S
  WCAG: 2.3.3 Animation from Interactions (AAA — best practice for MVP polish)

[2.6] Mobile touch targets below 44×44 px minimum
  File: apps/web/src/components/header.tsx:179-185 (burger `p-2` ≈ 36×40 px)
  File: apps/web/src/app/(fundraising)/layout.tsx:220-227 (menu button `h-9 w-9` = 36 px)
  Symptom: Primary navigation controls hard to activate on phones; fails WCAG 2.5.5 Target Size (AAA)
           and practical AA usability expectations for public/portal MVP.
  Fix: `min-h-11 min-w-11 flex items-center justify-center` on icon nav buttons.
  Effort: S
  Ref audit: PUBLIC [2.12] — STILL UNRESOLVED

[2.7] Chat widget icon buttons lack explicit focus-visible styling
  File: apps/web/src/components/chat-widget.tsx:256-330
  Symptom: Close/send/stop use hover colors only; rely on global `:focus-visible` outline which
           may be low-contrast on dark `bg-inverse-surface` buttons.
  Fix: Add `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2` matching Button component.
  Effort: S
  WCAG: 2.4.7 Focus Visible (AA)

[2.8] Sheet close control English screen-reader text
  File: apps/web/src/components/ui/sheet.tsx:51
  Symptom: `<span className="sr-only">Close</span>` — Swedish site should say "Stäng".
  Fix: Replace with "Stäng" (match dialog.tsx:45).
  Effort: S
  WCAG: 3.1.2 Language of Parts (AA)

[2.9] Kontakt page skips heading level (h1 → h3)
  File: apps/web/src/app/(marketing)/kontakt/page.tsx:51,137,156,175
  Symptom: Page h1 "Kontakta oss" then sidebar blocks use h3 ("E-post", "Adress") with no h2.
  Fix: Add h2 "Kontaktuppgifter" wrapping sidebar, or demote sidebar titles to h2.
  Effort: S
  WCAG: 1.3.1, 2.4.6

[2.10] Checkout inline error banner missing role="alert"
  File: apps/web/src/app/(shop)/shop/[slug]/kassa/page.tsx:186-189
  Symptom: Error shown in red box without `role="alert"` (Klarna error path at ~407 has it).
  Fix: Add `role="alert"` to top error container for immediate SR announcement.
  Effort: S
  WCAG: 4.1.3

[2.11] Data tables lack accessible name / caption
  File: apps/web/src/app/(portal)/portal/saljare/page.tsx; klubbar/page.tsx; bestallningar/page.tsx (pattern)
  Symptom: Dense `<Table>` grids have column headers but no `<caption>` or `aria-label` describing
           the table purpose — SR users hear cells without table context on entry.
  Fix: Add visually hidden `<caption>` or `aria-label="Säljare — översikt"` on `<Table>`.
  Effort: S
  WCAG: 1.3.1
