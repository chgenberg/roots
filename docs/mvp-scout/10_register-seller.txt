================================================================
SCOUT 10 — Seller registration via invite
================================================================
Date: 2026-05-25
Scope: `/registrera/saljare/[token]`, `POST /v1/auth/register/seller`, `packages/db` sellers + teams schemas
Role: SELLER
Ref: docs/flow-audits/SELLER_2026-04-18_1245.txt, MASTER_PLAN Fas 6

SUMMARY
-------
Core seller self-registration works end-to-end: valid team invite token → atomic user+seller insert → session cookie → redirect to `/min-shop`, where “Öppna min shop” opens a live `/shop/[slug]`. However, the landing page never validates or previews the invite (unlike `/registrera/lagansvarig/[token]`), registration ignores campaign status and minor-protection schema fields, and successful signup silently overwrites any existing browser session. These gaps block MVP-ready seller onboarding for a youth-heavy fundraising product.
Findings: 18 total (P1: 4, P2: 9, P3: 4, P4: 1)
MVP readiness: 52/100

P1 — CRITICAL (blocks MVP)
================================================================

[1.1] Silent session takeover when another user is logged in
  File: apps/api/src/routes/auth.ts:790-798; apps/web/src/app/(auth)/registrera/saljare/[token]/page.tsx (no session check)
  Symptom: Parent/coach logged in on shared device opens seller invite; successful signup overwrites `rootsSessionId` with new SELLER session — no warning, no merge, no logout-first prompt.
  Root cause: `createSession` + `setCookie` always runs after registration; page never reads existing session.
  Fix: Detect active session in API or page; return 409 `{ kind: "SESSION_CONFLICT" }` per MASTER_PLAN Fas 6; UI shows confirm-switch banner. Or force logout before showing form.
  Effort: M
  Ref audit: SELLER [1.1] — STILL UNRESOLVED

[1.2] No minor / guardian-consent workflow at seller signup
  File: apps/api/src/routes/auth.ts:719-828; apps/web/src/app/(auth)/registrera/saljare/[token]/page.tsx; packages/db/src/schema/users.ts:30-35
  Symptom: Youth sellers (primary persona) register with full legal name, no birth year, no guardian email/consent. Public shop exposes `displayName` + name-derived slug immediately.
  Root cause: Fas 6 schema fields (`birthYear`, `guardianUserId`, `guardianConsentAt`) added to DB but registration path never reads/writes them; no age gate UI.
  Fix: Add birth year (or age band) to form; if under 16 → collect guardian email, block public shop until consent token confirmed; default `hideFromLeaderboard` + suggest `publicAlias`.
  Effort: L
  Ref audit: SELLER [1.6], [1.7] — PARTIALLY IMPROVED (schema exists) but flow STILL UNRESOLVED

[1.3] Invalid invite token not rejected until form submit
  File: apps/web/src/app/(auth)/registrera/saljare/[token]/page.tsx (entire file — no useEffect preview)
  Symptom: User pastes wrong/expired/rotated invite URL, sees full signup form, fills 4 fields, submits → “Ogiltig inbjudningslänk.” Lagansvarig flow already GETs preview on mount (`registrera/lagansvarig/[token]/page.tsx:61-87`).
  Root cause: No public REST preview for team seller invites; tRPC `getByInviteToken` unused; page is submit-only.
  Fix: Add `GET /v1/auth/seller-invites/:token` (or reuse tRPC from page) returning teamName, orgName, campaignName; on 404 render `<InviteNotFound />`; mirror lagansvarig UX.
  Effort: M
  Ref audit: SELLER [2.1], [2.3] — STILL UNRESOLVED

[1.4] Registration allowed when campaign is not ACTIVE
  File: apps/api/src/routes/auth.ts:734-742 (team lookup only — no campaign status join)
  Symptom: Seller completes signup for a team whose campaign is ENDED/SETTLED; lands on min-shop with shop visible but checkout disabled (`shop/[slug]/page.tsx:108-113`). Wasted onboarding — seller cannot earn.
  Root cause: `/register/seller` validates team token existence but not linked `campaigns.status`.
  Fix: Join campaign in handler; reject non-ACTIVE with 410 + message “Kampanjen är avslutad”; show same on invite preview.
  Effort: S

[2.1] No org/team/campaign trust context before signup
  File: apps/web/src/app/(auth)/registrera/saljare/[token]/page.tsx:95-98; apps/api/src/trpc/routers/campaigns.ts:226-259
  Symptom: Generic “Skapa ditt konto och få din personliga shop direkt” — seller cannot verify they’re joining the right lag/förening/kampanj (SMS templates include leader name; page cannot).
  Root cause: Missing invite preview fetch (see [1.3]); `getByInviteToken` omits leader name.

  Effort: M
  Ref audit: SELLER [2.1], [2.2], [2.6] — STILL UNRESOLVED

[2.2] API skips `RegisterSellerSchema` — password length not enforced server-side
  File: packages/contracts/src/auth.ts:56-62; apps/api/src/routes/auth.ts:727-731
  Symptom: Client requires ≥8 chars; API only checks truthy `password`. Direct API call with 1-char password succeeds.
  Root cause: Zod schema defined in contracts but not parsed in route handler (unlike pattern expected for other register endpoints).
  Fix: `RegisterSellerSchema.safeParse(body)` before DB work; return 400 with field errors.
  Effort: S
  Ref audit: SELLER [2.22] — STILL UNRESOLVED

[2.3] 409 duplicate email — no login + bind-invite path
  File: apps/api/src/routes/auth.ts:750-751; page.tsx:55-57
  Symptom: Existing user gets “E-postadressen är redan registrerad.” with no link to `/login?next=/registrera/saljare/{token}` or “logga in och gå med i laget”.
  Root cause: No account-linking flow for invites.
  Fix: On 409, UI offers login CTA preserving token in `next`; post-login endpoint to attach seller row to team (if user is SELLER/PUBLIC).
  Effort: M
  Ref audit: SELLER [2.4] — STILL UNRESOLVED

[2.4] Welcome email login link 404 (`/logga-in`)
  File: apps/api/src/lib/email/templates.ts:61
  Symptom: Post-signup email button “Logga in” → `/logga-in`; no such route in `apps/web` (login is `/login`).
  Root cause: Stale path in template.
  Fix: Change to `${siteUrl()}/login`; for sellers add secondary CTA “Öppna min shop” → `/min-shop`.
  Effort: S

[2.5] Swedish names produce broken shop slugs
  File: apps/api/src/routes/auth.ts:756-759 (same pattern in dashboard.ts:513-516)
  Symptom: “Östen Lindström” → slug like `---sten-lindstr-m-abc123` after non-ASCII strip; ugly share URLs, harder to remember.
  Root cause: `replace(/[^a-z0-9]/g, "-")` after naive `toLowerCase()` without transliteration.
  Fix: Use `slugify` with Swedish locale or strip diacritics (`ö→o`); collapse repeated hyphens; consider `publicAlias` for display vs slug (Fas 6).
  Effort: S
  Ref audit: SELLER [2.9] — STILL UNRESOLVED

[2.6] Privacy fields in schema not collected at registration
  File: packages/db/src/schema/sellers.ts:43-45; auth.ts:774-780
  Symptom: Minors cannot set pseudonym, hide from leaderboard, or personal message at signup — defaults expose real name on public shop and team ranking.
  Root cause: Fas 6 columns added without form/API wiring.
  Fix: Optional signup step (or expandable section): publicAlias, hideFromLeaderboard checkbox, personalMessage textarea; persist in same tx.
  Effort: M
  Ref audit: SELLER [1.8], [1.9] — SCHEMA IMPROVED since April audit; UI/API STILL UNRESOLVED

[2.7] Logged-in user sees full signup form (no branch)
  File: apps/web/src/app/(auth)/layout.tsx; registrera/saljare/[token]/page.tsx
  Symptom: TEAM_LEADER or ASSOCIATION_ADMIN opens seller invite on same browser — can create second account or hit 409 on own email without guidance.
  Root cause: Auth layout has no session probe; no “already logged in as X” banner.
  Fix: Fetch `auth.me` on mount; if session exists show context + logout / use different account.
  Effort: S
  Ref audit: SELLER [2.5] — STILL UNRESOLVED

[2.8] Success screen lacks immediate clickable shop link
  File: apps/web/src/app/(auth)/registrera/saljare/[token]/page.tsx:70-86
  Symptom: After signup, user sees `/shop/{slug}` as plain text and waits 2s — cannot open shop immediately to verify; bad for “Visa min shop” acceptance test.
  Root cause: Success UI is passive; redirect timer only.
  Fix: Add primary `<a href="/shop/{slug}">Visa min shop</a>` + secondary “Gå till dashboard”; reduce or remove fixed delay.
  Effort: S

[2.9] No `/registrera/saljare` index — tokenless URL 404
  File: apps/web/src/app/(auth)/registrera/saljare/ (only `[token]/page.tsx`)
  Symptom: `/registrera/saljare` without token → Next.js 404; marketing copy or SMS truncation may land here.
  Root cause: No fallback page explaining “you need an invite link from your lagledare”.
  Fix: Add `registrera/saljare/page.tsx` with helpful copy + link to support.
  Effort: S
